# Language audit — 2026-10-29

Scope: the four shipped languages (English, Spanish, Arabic, Hebrew) across
the translation files, the interactive app, the server-rendered pages, the
AI analyst, typography, right-to-left layout, first-paint behaviour, SEO and
the data itself. Then a recommendation on which languages to add.

| Area | State found |

## 2. Translation corrections made

Spanish
- `eventPanel.claimed` "Reclamado" (reclaimed/demanded) → "Alegado".
- Fatalities were "Víctimas" (victims, includes wounded) in six places → "Muertes" / "Civiles muertos".
- `nav.feed` and the landing feature "Noticias" (news) → "Eventos"; `nav.dispatches` "Partes" (ambiguous) → "Boletines".
- "Miembros del servicio muertos/heridos" (calque) → "Militares muertos/heridos"; "Costos de envío" (parcel shipping) → "Costos del transporte marítimo".
- Contact text now first person like the English ("escríbeme", "me tomo … en serio").

Arabic
- `eventTypes.violence_against_civilians` "إصابات مدنية" (civilian injuries) → "ضحايا مدنيون".
- `eventPanel.eventFeed` "تغذية الأحداث" (a calque of "feed" as nourishment) → "سجل الأحداث"; `nav.feed` "الأخبار" → "الأحداث"; `nav.dispatches` → "النشرات".
- Zero forms: "٠ حدث" → "لا أحداث", "٠ حالة وفاة" → "لا وفيات مُبلّغ عنها".
- "هنگاو" used a Persian گ that does not exist in Arabic → "هنغاو"; the one Western "2026" → "٢٠٢٦".

Hebrew
- `eventPanel.copied` was stored as "!הועתק" (punctuation on the wrong side in logical order) → "הועתק!".
- "כלי טיס" (aircraft) for drones in four places → "כטב״ם" / "כטב״מים".
- `sources.howWeSource` "כיצד אנו מקורות ומאמתים" (a noun used as a verb) → "כיצד אנו אוספים ומאמתים נתונים".
- `donate.namedEvent` "אירוע מצוין" (an excellent event) → "אירוע מזוהה"; "עלויות משלוח" → "עלויות הובלה ימית".
- `app.live` "שידור חי" (live broadcast) → "חי"; `eventPanel.eventFeed` → "יומן אירועים".
- Mixed register (masculine singular "אתה" next to plural imperatives) moved toward gender-neutral forms in the privacy and terms text. A native pass on register across the whole file is still worth doing.

## 3. Structural fixes made

1. **Server-side locale** (`src/i18n/server.ts`): cookie, then `Accept-Language` (parsed with q-weights), then English. The root layout, the home wrapper and the three content-page wrappers resolve it once and seed the client provider, so the first byte is in the right language and direction. New unit tests cover the parser and the resolution order.
2. **Server pages translated**: a new `pages` namespace (112 keys in all four files) drives the nav, event page, country index and hubs, dispatch index and pages, the by-the-numbers table and the newsletter box. Dates and numbers use the locale. Event descriptions, evidence quotes and dispatch prose stay English and are marked `lang="en" dir="ltr"`, with a one-line notice in non-English locales. The codebook remains English (it is the reference for the English field names).
3. **Language switcher on server pages** (`LocaleSwitcher`): sets the same cookie and localStorage key as the app's switcher and reloads.
4. **Shared `LOCALE_TAG`**: every `Intl` call, client and server, uses the same tags; Arabic pins `nu-arab` so digits match the strings everywhere.
5. **RTL overlay**: `md:end-[380px]`.
6. **Hebrew webfont**: Noto Sans Hebrew via next/font.
7. **AI analyst**: one registry-driven prompt plus a language directive per language; the dead prompt table and its tests removed. A second conflict now reaches every language without touching the prompt.
8. **End-to-end**: Arabic, Hebrew and Spanish browsers get the right `lang`/`dir` and translated headings on the server pages, and the switcher round-trips.

## 4. Still open (ranked)

1. **Content is English.** The biggest remaining gap for a non-English reader is the event description and the dispatch body. Options: (a) machine-translate `description` and `civilian_impact` for new events at extraction time and backfill the archive once (Haiku 5.5, roughly 150 output tokens per event per language; the 37k-row archive is about 5.6M output tokens per language, well under $5 per language at $0.50 per million output tokens, plus input; ongoing cost is cents a day), stored as `description_i18n` and shown with a "machine translated" marker; (b) translate dispatches per language at publish time (one extra call per language, about a cent each). Both keep English as the canonical record. This is a product decision because it changes what the site asserts in each language.
2. **URL-based locales and `hreflang`.** With one URL per page, search engines index English only. Serving `/ar/…`, `/he/…`, `/es/…` for the content pages (middleware rewrite, canonical per language, `hreflang` cluster) is what makes Arabic search traffic possible. Medium effort; best done together with item 1 so the localized URL has localized content.
3. **Sentence assembly in the app.** The overview banner, landing briefing and Ask panel build sentences from counts and fragments ("N verified events across M countries"). The current fragments happen to read correctly in all four languages; they will not for every language. Convert to parameterised strings when adding the next language.
4. **Hebrew register pass** by a native speaker; Arabic plural agreement for `time.*` (دقيقة/دقائق) via the plural object pattern already used on the map.
5. **Metadata per language** only makes sense after item 2.
6. The landing subtitle hard-codes "2026 Iran War" in four languages; derive from the registry when the second conflict activates.

## 5. Which languages next

Criteria: who the conflicts are about, who reports on them, who is likely to search for a map-first tracker, and what the site can sustain (each language is 500 strings, a chat directive, a font, a native review, and, if item 4.1 ships, per-event translation at cents a day).

| Language | Why | Script / layout | Cost to add |
|---|---|---|---|
| **Persian (fa)** | The war is on Iran. The Persian-language audience (inside Iran via VPN, and the diaspora in the US, Germany, Canada, UK) is large and underserved by neutral, source-attributed trackers; BBC Persian and Iran International are the reference points. First choice. | RTL, Arabic script with four extra letters; Noto Sans Arabic covers them, Vazirmatn is the preferred Persian face. RTL plumbing already exists. | Low: strings + font + directive. Persian uses Persian digits (۰-۹), a separate `nu-arabext` tag. |
| **French (fr)** | Second conflict is the Sahel (Mali, Burkina Faso, Niger: French is the working language of press and government). Also Lebanon, Chad, Algeria, and a real French share in today's visitors. Sudan coverage in French is strong too (RFI, France 24). | LTR, Latin. | Low. |
| **Turkish (tr)** | Turkey is an actor in the registry; large domestic news consumption; Turkish-language OSINT community is active. | LTR, Latin with diacritics. | Low. |
| **Urdu (ur)** | Pakistan mediates in the current conflict; 230M speakers; almost no Urdu-language conflict trackers. | RTL, Nastaliq preferred (Noto Nastaliq Urdu); line-height needs care. | Medium (font metrics). |
| Russian (ru) | Russia is a party to the diplomacy; large audience; but a crowded space and a hostile information environment. | LTR, Cyrillic. | Low. Worth it after the four above. |
| German (de) | Large diaspora audiences for both Iran and Sudan; strong public-broadcaster coverage. | LTR. | Low. Nice to have. |
| Chinese (zh) | The log shows 31 unique "zh" IPs, more than Spanish; energy and Hormuz interest is real, but much of that traffic looks automated. | LTR. | Low. Revisit once real traffic is confirmed. |
| Hausa, Bambara, Fulfulde | Sahel local languages. Right in principle; the pipeline's sources are not in them, and machine translation quality is weaker. | LTR. | Park until French is live and the Sahel conflict is active. |

Recommendation: **Persian and French next**, in that order, then Turkish and Urdu once Sudan or the Sahel is active. Add them one at a time; ship each with the content-translation layer (4.1) so the language is more than chrome.
